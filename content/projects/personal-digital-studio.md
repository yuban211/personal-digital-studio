## 它是什么

一个独立的个人站点，和 Garden Action 部署在同一台服务器上，但完全隔离：独立的应用、独立的数据库、独立的 `/studio` 路径前缀。

## 技术选型

**Python + Jinja2 服务端渲染，不引入前端框架。**

这个决定一开始并不好做——参考的站点是 Vue 全栈，组件化程度很高。但有几个理由让我坚持了 SSR：

- 整站没有登录态，页面内容对所有人一样，客户端渲染的收益基本为零
- 首屏时间更可控，不需要等 JS 下载执行完才有内容
- 服务器只有 SFTP，没有 shell，依赖必须离线打包上传——少一个前端构建链就少一份负担
- 动效用原生 JS + Canvas 实现，比引入框架更轻

代价是模板里的逻辑会稍微啰嗦一点。这个代价我认为可以接受。

## 视觉与动效

- **纵向分屏翻页**：内层内容滚到边界才翻页，不是滚一段就跳
- **天气场景引擎**：Canvas 粒子系统，七种预设（晴/多云/雨/雷暴/雪/风/雾）
- **Hero 揭幕**：三行标题依次升起，飞船用纯 CSS 三角做矢量抖动
- **令牌化动效**：微交互 160ms、状态 280ms、揭幕 620ms、转场 480ms、品牌 1100ms

动效全部尊重 `prefers-reduced-motion`。

## 后台

自建的管理后台，项目和日志都是可视化编辑，图片直接传进媒体库。密码用 scrypt 哈希，会话 cookie 是 HMAC 签名，表单带 CSRF 校验，登录接口有限速。

**仓库同步**：后台可以直接从 GitHub 拉取 Markdown 批量更新项目和文章。同步只读取文本，绝不执行仓库里的任何代码。
