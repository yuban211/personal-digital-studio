## 起因

想要一个属于自己的浏览器首页。第一反应是装扩展，但更省事的做法是直接让新标签页指向自己的站点——不用插件，不用维护一份会过期的副本。

Chrome 提供了 `chrome_url_overrides` 这个能力，声明了之后，新标签页就由你的页面接管。

## 最小可用版本

```json
{
  "manifest_version": 3,
  "name": "个人数字工作室",
  "version": "1.0.0",
  "chrome_url_overrides": {
    "newtab": "newtab.html"
  }
}
```

就这么几行。没有后台脚本，没有权限申请，没有 content script。

## 实测比想象复杂

在国产 Chromium 内核浏览器（星愿 10.13，Chromium 128）上验证时，遇到几个和预期不一样的地方：

- **`chrome://extensions/` 会被劫持**。用 `--load-extension` 启动后，浏览器把自己的内置新标签页塞回来，扩展管理页根本进不去。
- **改注册表行不通**。浏览器的偏好项（`homepage`、`session.startup_urls`）都带 MAC 校验，直接写注册表会被忽略或损坏。
- **崩溃上报会被沙箱打断**。命令行启动时如果 crashpad 起不来，浏览器会立刻自杀退出。

最后是靠一个探针扩展确认了真相：加载时浏览器弹出提示框，说「此网页被扩展程序 XXX 更改了」——这说明 `chrome_url_overrides` 确实被识别了。

## 但这不是最终答案

`chrome_url_overrides` 要求扩展必须安装到浏览器里。对「想让新标签页指向某个网址」这个需求来说，浏览器自带的「设置 → 启动页面」就够了，不需要任何扩展。

真正需要扩展的场景是：**新标签页要有交互**——渲染实时天气、播放音乐、跑一个轮播。单纯的跳转不值得装插件。

## 一点判断

做之前先问一句：这个需求是「换个网址」还是「要一个应用」？

前者用浏览器设置，五分钟搞定；后者才值得写扩展。两者混在一起时，先做前者，再决定要不要升级到后者。
