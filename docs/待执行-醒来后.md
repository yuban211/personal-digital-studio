## 上线前已修的三处（本地，已完成）

1. **静态资源全 404（P0）**：`src/static/web/index.html` 里 `style.css` / `config.js` / `search.js` / `app.js` 改为 `web/xxx`，与 `app.py` 的 `mount("/web")` 对齐。原写法上线后页面无样式、搜索框不响应。
2. **反代前缀兼容**：`app.py` 在配了 `APP_PREFIX` 时额外挂一份 `<prefix>/web`，剥前缀与不剥前缀两种 Caddy 配置都能命中。
3. **密钥**：`scripts/startpage.env` 的 `APP_SECRET` 换为随机值；`SYNC_TOKEN` 设了随机值（前端不调用该接口，等于关掉公网写入）。

## 第 1 步：上传产物

把 `D:\.211\起始页V2\dist\startpage-v2.tar.gz` 传到服务器 `/workspace/`（面板文件管理或 SFTP 均可）。

## 第 2 步：解包覆盖

```bash
mkdir -p /workspace/startpage && tar xzf /workspace/startpage-v2.tar.gz -C /workspace/startpage && chmod +x /workspace/startpage/scripts/run-server.sh && ls /workspace/startpage/src/static/web
```

期望最后一行列出 `index.html app.js config.js search.js style.css`。

## 第 3 步：切换 Caddy 到 9103

```bash
cp /workspace/Caddyfile /workspace/Caddyfile.bak-v1 && cp /workspace/Caddyfile.v2 /workspace/Caddyfile && grep -n "9103" /workspace/Caddyfile
```

看到 `reverse_proxy 127.0.0.1:9103` 即成功。若 `Caddyfile.v2` 已不在服务器上，需在 `/studio/*` 段把端口由 9102 改成 9103。

## 第 4 步：切换开机启动脚本

```bash
cp /workspace/start.tls.sh /workspace/start.tls.sh.bak-v1 && cp /workspace/start.v2.sh /workspace/start.tls.sh && chmod +x /workspace/start.tls.sh && bash -n /workspace/start.tls.sh && echo SCRIPT_OK
```

必须看到 `SCRIPT_OK` 才继续（`bash -n` 是语法闸门）。

## 第 5 步：重启容器

MCSManager 面板点「重启」。重启后 V2 在 9103 自启。

## 第 6 步：验证（四条，全绿再动 V1）

```bash
sleep 25
curl -s -o /dev/null -w "studio=%{http_code}\n" https://yuban211.duckdns.org:59684/studio/
curl -s -o /dev/null -w "css=%{http_code}\n"    https://yuban211.duckdns.org:59684/studio/web/style.css
curl -s -o /dev/null -w "js=%{http_code}\n"     https://yuban211.duckdns.org:59684/studio/web/app.js
curl -s -o /dev/null -w "garden=%{http_code}\n" https://yuban211.duckdns.org:59684/
```

- `css` 与 `js` 必须是 **200**。若 404，说明 Caddy 前缀处理与静态挂载仍不匹配，**停在这里回滚**，不要进第 7 步。
- 浏览器打开 `https://yuban211.duckdns.org:59684/studio/`：应见大搜索框（已聚焦）、时间问候、快捷入口、待办；标题应为「起始页」，不是「高冷的网友 208」。

## 第 7 步：删除 V1（验证全绿后）

```bash
rm -rf /workspace/newtab /workspace/newtab-db /workspace/newtab-admin.json /workspace/newtab.log /workspace/newtab.pid /workspace/startpage-v2.tar.gz && echo V1_GONE
```

⚠️ `/workspace/newtab-db` 是 V1 唯一数据目录，删前确认第 6 步全绿；本机已有备份。

## 回滚（任一步出问题）

```bash
cp /workspace/Caddyfile.bak-v1 /workspace/Caddyfile && cp /workspace/start.tls.sh.bak-v1 /workspace/start.tls.sh
```

然后面板重启，V1 恢复。

## 已知坑

| 坑 | 说明 |
|---|---|
| 依赖安装 | `run-server.sh` 只在 `import fastapi` 失败时才 `pip install`（清华源）。容器出网受限会卡在此处，表现为 9103 不通。 |
| 数据目录 | 线上用 `/workspace/startpage-db/`，与 V1 的 `newtab-db` 完全隔离，切版本不污染数据。 |
| 前端不调 API | `app.js` 只把「服务器 API」地址存进 localStorage，从不发请求；`SYNC_TOKEN` 设成非空不影响任何功能。 |
| 本地跑测试 | 本机 pip 被拦截（任何索引返回 `from versions: none`），`tests/` 需在服务器或先手工下 wheel 才能跑。 |
