# PRD —— 浏览器起始页 V2

> V2 完全放弃前一代（V1）的业务代码，只保留基础框架并做优化。
> 本文件是唯一开发依据。

---

## 0. 与 V1 的关系

| 项 | V1 | V2 |
|---|---|---|
| 形态 | 服务端渲染站点为主 + 扩展 | **纯浏览器扩展（本地优先）** |
| 数据 | SQLite（服务器） | **localStorage（浏览器本地）** |
| 服务器 | 必需 | **可选**（只做内容同步） |
| 搜索 | 交给浏览器 omnibox（不可控） | **显式引擎表**（Bing 默认，可切换/自定义） |
| 依赖 | FastAPI + Jinja2 + uvicorn | **零运行时依赖**（原生 JS） |
| 天气 | 服务器调用心知天气 | 扩展本地调用（公开 API） |

**保留的基础框架**：配置管理、数据层、仓储层、安全模块、依赖注入、启动脚本。
**放弃的**：SSR 页面模板、后台管理、仓库同步、天气模块、旧前端组件。

## 1. 产品目标

**一句话目标**：做一个装在浏览器里的起始页扩展，打开新标签就能搜索、看常用站点、看时间和天气，数据存在本地。

**设计原则**：
1. **本地优先** —— 不登录、不联网也能用；联网只是增强
2. **零构建** —— 原生 HTML/CSS/JS，不用打包器（本机 npm 不可达，且零构建更稳）
3. **零外部依赖** —— 不引 CDN、不引字体图标（历史教训：本机所有 CDN 不可达）
4. **可配置** —— 搜索引擎、壁纸、快捷入口都能改

## 4. 模块定义

### 4.1 搜索（核心，借鉴 mtab 做法）

```js
const ENGINE_URLS = {
  bing:    "https://www.bing.com/search?q=",
  google:  "https://www.google.com/search?q=",
  duckduckgo: "https://duckduckgo.com/?q=",
  baidu:   "https://www.baidu.com/s?wd=",
};
// 自定义引擎用 {} 占位
custom: "https://example.com/search?q={}"
```

**为什么不用"交给浏览器 omnibox"**（V1 的做法）：
- 不可预测：用户装了搜索扩展就会跳到别处
- 无法切换引擎
- mtab 验证过显式引擎表更好

**搜索栏增强**（可选，零依赖可实现）：
- 输入 `=表达式` → 计算器
- 输入域名或 URL → 直接打开而非搜索

### 4.2 快捷入口
- 数据：本地存储 `{title, url, icon}`
- 操作：增删、拖拽排序（后续）
- 图标：用首字母色块（不引图标库）

### 4.3 天气
- 调用公开 API（Open-Meteo，免密钥）
- 失败或不联网：隐藏该模块，不报错

### 4.4 待办/笔记
- 纯本地 localStorage
- 增删改查

### 4.5 服务器同步（可选）
- 填了 API 地址才启用
- 拉取项目/日志只读展示
- 拉不到就静默跳过

## 5. 数据持久化

| 数据 | 位置 | 说明 |
|---|---|---|
| 配置（引擎/壁纸/模块开关） | `chrome.storage.local` | 扩展原生存储 |
| 快捷入口、待办 | `localStorage` | 本地优先 |
| 服务器内容 | 远程 API | 可选，失败不影响 |

**备份**：设置页提供"导出 JSON / 导入 JSON"。
